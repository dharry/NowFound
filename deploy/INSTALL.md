# NowFound インストールガイド

[toc]

## 1. 製品説明

NowFound は、フォルダ配下のファイル名・フォルダ名を高速に検索するオンプレミス向けの Web アプリケーションです。外部 CDN やクラウドに依存せず、オフライン環境でも動作します。

| コンポーネント | 役割 |
|---|---|
| Web（`web/`） | ログイン、検索、ユーザー／グループ／検索対象フォルダの管理、操作ログの閲覧 |
| Indexer（`indexer/`） | 検索対象フォルダを走査して `files.db` を更新する（毎日 05:30 に自動実行） |

- データベース（`main.db` / `files.db` / `ope.db`）は配布物直下の `data/` に作られます。**ローカルディスク**に置いてください（SMB/NFS 上は不可）。
- 事前に .NET 10 ランタイム（ASP.NET Core）をインストールしてください。



## 2. インストール

### Windows

**インストーラーを使う場合（推奨）**: `NowFound-Setup-<バージョン>.exe` を管理者権限で実行します。`C:\NowFound`（既定。変更可）にファイルを配置し、Web サービス（HTTPS 5002、ファイアウォール許可を含む）と、毎日 05:30 の Indexer タスクを自動で登録します。初回のインストールでは初期管理者も作成されます。**すでにインストール済みの場合は、同じインストーラーを実行するとアップデートになります**。プログラムファイルだけを更新し（サービスを止めて入れ替え、再び開始）、サービス・タスクスケジューラの登録、データ、証明書、`appsettings.Production.json` はそのままです。アンインストールは「アプリと機能」から行い、サービス・ファイアウォール許可・タスクも削除されます（データフォルダを削除するかは確認されます）。サイレント実行は `/VERYSILENT` です（アンインストール時はデータを残します）。

**zip を使う場合**:

`NowFound-publish.zip`を展開し、管理者権限の PowerShell で、展開したフォルダ内で実行します。

```powershell
.\register-web-service.ps1 -Seed        # Web をサービス登録して起動（初回のみ -Seed で初期管理者を作成）
.\register-indexer-task.ps1             # Indexer をタスクスケジューラに登録（毎日 05:30、SYSTEM）
```

- Web サービスは低権限の **LocalService** アカウントで動作します（Indexer は検索対象フォルダを走査するため SYSTEM）。登録時に、LocalService へ `data/`（変更）、`web/` と `certs/`（読み取りと実行）の権限だけを付与します。独自の証明書を `certs/` 以外に置く場合は、LocalService に読み取り権限を付けてください。
- 以前のバージョン（LocalSystem で登録済み）から切り替えるには、`.\register-web-service.ps1` を再実行します（サービスを登録し直し、LocalService へ変更します）。インストーラーでのアップデートは登録を変更しないため、再実行が必要です。
- 登録時に Windows ファイアウォールの TCP 5002 を開放します（サービス削除時に閉じます）。
- 削除: `-Unregister` を付けて再実行
- コンソールで試す場合: `run-web.bat seed`
- Indexer を今すぐ実行: `Start-ScheduledTask -TaskName 'NowFound Indexer'`

### HTTPS と証明書

Web は既定で **HTTPS（ポート 5002）** で待ち受けます（`https://<サーバー名>:5002`）。HTTP は使えません（Production ではログインクッキーが HTTPS 専用のため、HTTP ではログインできません）。

- 運用の証明書は、社内 CA で発行してください（手順は下の「社内 CA（AD CS）の証明書で運用する」）。
- 証明書 `certs/nowfound.pfx` は、**インストール時（初回のサービス登録時）にそのサーバー上で生成される自己署名証明書**です（配布物には秘密鍵を含めません。名前は `nowfound.invalid` / `localhost` / サーバー名、有効期限 10 年）。パスワードはランダムに生成され、`web/appsettings.Production.json` の `Certificate:Password` に書き込まれます。すでに `certs/nowfound.pfx` がある場合は上書きしません（アップデートでも維持されます）。自己署名のため、ブラウザに「安全ではない」警告が出ます。
- **運用では、利用者側で適切な証明書に差し替えてください**（社内 CA や正規の CA が発行した、実際のサーバー名を含む証明書）。
  1. 証明書（PFX）を `certs/` に置く。
  2. `web/appsettings.Production.json` の `Certificate:Path` と `Password` を書き換える。ポートを変える場合は `Url` も変更し、ファイアウォールも合わせて変更する。
  3. Web を再起動する（`Restart-Service NowFound`）。
- 自己署名証明書を作り直す場合（Windows。配布物直下の `new-cert.ps1` が `certs/` に出力します）: `.\new-cert.ps1 -DnsName nowfound.invalid,localhost -Password "<パスワード>"`。`web/appsettings.Production.json` の `Password` も合わせて書き換え、Web を再起動します。作成した `nowfound.cer` をクライアント PC の「信頼されたルート証明機関」に登録すれば、警告は出なくなります。

#### 社内 CA（AD CS）の証明書で運用する（Windows）

オンプレミス運用では、同梱の自己署名証明書ではなく、社内 CA が署名したサーバー証明書を使います。クライアント PC には、CA のルート証明書（中間 CA がある場合は中間証明書も）を AD のグループポリシーで配布します。**配布するのは CA の証明書（公開鍵のみ）で、サーバー証明書の PFX（秘密鍵付き）は配布しません。**

**手順 1: サーバー証明書を発行する**（NowFound サーバーで、管理者の PowerShell を使います。2 つの手順は同じサーバーで実行してください）

1. CSR を作成します。`-DnsName` には、利用者がブラウザに入力するサーバー名をすべて指定します（最初の名前が CN になり、すべてが SAN に入ります）。

   ```powershell
   .\new-cert.ps1 -Csr -DnsName nowfound.invalid,nowfound
   ```

   `certs\nowfound.csr` が作成されます。秘密鍵はこのサーバー内に作られ、CSR だけがファイルになります。
2. CSR を CA に提出し、発行された証明書（`.cer`）を保存します。AD CS の Web 登録（`https://<CA サーバー>/certsrv`）を使う場合は、「証明書の要求の詳細設定」で CSR の内容を貼り付け、テンプレートに「Web サーバー」系のものを選びます。コマンドで行う場合の例です。

   ```powershell
   certreq -submit -attrib "CertificateTemplate:WebServer" certs\nowfound.csr server.cer
   ```
3. 発行された証明書を取り込み、PFX にします。`-Password` には、新しい PFX のパスワードを指定します（既定のパスワードは使えません）。

   ```powershell
   .\new-cert.ps1 -Import server.cer -Password "<強いパスワード>"
   ```

   `certs\nowfound.pfx` が（証明書チェーン付きで）作成され、秘密鍵はサーバーの証明書ストアから削除されます。
4. `web\appsettings.Production.json` の `Certificate:Path`（`../certs/nowfound.pfx`）と `Password` を、手順 3 のパスワードに書き換えます。
5. Web サービスを再起動します（`Restart-Service NowFound`）。

**手順 2: ルート証明書／中間証明書をグループポリシーで配布する**

CA が Enterprise CA（AD 統合）の場合、ルート証明書は AD によってすでに配布されていることがあります。先にクライアントの `certmgr.msc` で「信頼されたルート証明機関」を確認してください。

1. CA のルート証明書（と中間証明書）を `.cer` で書き出します（CA サーバーで `certutil -ca.cert rootca.cer`。中間 CA の証明書は、サーバー証明書の「証明のパス」から書き出せます）。
2. ドメインコントローラー、または RSAT のある管理 PC で「グループポリシーの管理」（GPMC）を開き、対象のクライアント PC を含む OU に GPO を作成してリンクします。
3. GPO を編集し、`コンピューターの構成` → `ポリシー` → `Windows の設定` → `セキュリティの設定` → `公開キーのポリシー` を開きます。
   - 「信頼されたルート証明機関」を右クリックして「インポート」し、ルート証明書を登録します。
   - 中間 CA がある場合は、「中間証明機関」に中間証明書を登録します。
4. クライアント PC で `gpupdate /force` を実行し（反映には再起動または再ログオンが必要な場合があります）、`certmgr.msc` で証明書が登録されたことを確認します。
5. ブラウザで `https://nowfound.invalid:5002` を開き、警告が出ないことを確認します。

- Firefox は Windows の証明書ストアを使いません。利用者がいる場合は、ポリシー（`security.enterprise_roots.enabled`）の配布が必要です。
- CA の証明書の有効期限が切れると、全クライアントで警告が出ます。更新の時期を管理してください。
- サーバー証明書は期限前に、手順 1 で作り直して差し替えてください。

- リバースプロキシ（nginx、IIS など）で TLS を終端する場合は、`ForwardedHeaders:KnownProxies` にプロキシの IP を設定してください。
- 同梱の証明書の秘密鍵は配布物に含まれているため、**インターネットに公開する環境では必ず差し替えてください**。

### サブディレクトリ方式（1 台のサーバーで複数の Web アプリを公開する場合）

既定は、`https://<サーバー名>:5002/` のようにルート直下で公開するドメイン方式です。リバースプロキシで `https://<サーバー名>/nowfound/` のようにパスで振り分ける場合は、`web/appsettings.Production.json` に `PathBase` を追加します。

```json
{
  "PathBase": "/nowfound"
}
```

- 値は任意のパスに変更できます（例: `/apps/file-search`）。英数字・`.`・`_`・`~`・`-` が使えます。空にするとドメイン方式に戻ります。変更後は Web サービスを再起動してください。
- プロキシは `/nowfound` を**外さずに**そのまま Kestrel へ転送してください（nginx なら `proxy_pass http://127.0.0.1:5002;` のように末尾にパスを付けない）。
- 複数のアプリは、Kestrel を別ポート（`Kestrel:Endpoints:Https:Url`）で起動し、プロキシで振り分けます。
- ログイン Cookie などは `PathBase` の配下にだけ送られるため、同じホストの別アプリとは混ざりません。

### 共通の注意

- 同梱のスクリプト（`register-web-service.ps1`、`register-indexer-task.ps1`、`run-web.bat`、`run-indexer.bat` など）は、`-h` / `--help` / `-help` で使い方を表示します。
- アップグレードは新しい配布物で同じ手順を再実行します（`data/` は保持されます）。`web/appsettings.Production.json` を差し替えた場合は、上書きされないようバックアップしてから展開してください。



## 3. 利用方法

### 1. ログインと初期設定

1. ブラウザで Web の URL を開き、初期管理者でログインします。
   - アカウント: `admin@nowfound.invalid` ／ パスワード: `password123!`
   - 初回ログイン時にパスワード変更が求められます。以降は「ユーザー設定」の中の「パスワード変更」から変更できます。
2. 検索対象フォルダ: 検索したいフォルダ（サーバー上の絶対パス）を登録します。除外パターン（`*.tmp`、`node_modules` など。`*` `?` 可）や隠しフォルダ除外を設定できます。
3. ユーザー管理: ユーザーをメールアドレスで追加します（初回ログイン時のパスワード変更要求は選択可）。一覧の「編集」から、有効／無効、有効期限、ロックの解除、ユーザーの削除ができます。
4. グループ管理: グループを作り、メンバーと閲覧できる検索対象フォルダを割り当てます。ユーザーは複数グループに所属でき、管理者はすべて参照できます。

### 2. ファイル情報の取得

検索対象フォルダの内容は Indexer が `files.db` に取り込みます。登録直後に検索したい場合は Indexer を手動で実行してください（`run-indexer.bat`）。

- `--full` を付けると全件を走査し直します（週 1 回など定期的な実行向け）。通常は変更分のみを高速に反映します。
- 同じ `files.db` に対して複数の Indexer を同時に実行しないでください。

### 3. 検索

- 画面左のナビゲーションで検索対象フォルダを選び、ドリルダウンで絞り込めます。
- 上部の検索欄で、すべて／ファイル名／フォルダ名／拡張子／日付範囲を指定でき、AND/OR による複合検索が可能です。
- ページサイズはユーザー設定で個別に変更できます。

### 4. 操作ログ（管理者）

ログイン／ログアウト／アクセスエラーや、ユーザーが行った検索クエリを、日時・操作・ユーザーで検索して確認できます。
